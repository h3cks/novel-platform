# Документація з лінтингу (Linting)

## Обраний лінтер
Для проєкту обрано **ESLint** у зв'язці з **Prettier** та плагінами `@typescript-eslint`.
**Причини вибору:** Це індустріальний стандарт для TypeScript/Node.js проєктів. ESLint чудово знаходить логічні помилки та вразливості, а Prettier відповідає за єдиний стиль форматування коду команди.

## Базові правила
- `no-console: warn` — попереджає про використання `console.log` у production коді.
- `@typescript-eslint/no-explicit-any: warn` — мінімізація використання типу `any` для збереження переваг статичної типізації.
- `@typescript-eslint/no-unused-vars: error` — забороняє залишати невикористані змінні, щоб не засмічувати пам'ять.
- `prettier/prettier: error` — суворе дотримання стилю (відступи, лапки).

## Інструкція з запуску
- Запуск перевірки: `npm run lint`
- Автоматичне виправлення проблем: `npm run lint:fix`
